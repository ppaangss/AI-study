# Skip List

**"급행 노선을 얹은 정렬 연결 리스트."** Redis Sorted Set의 내부 자료구조.

## 문제: 정렬 연결 리스트는 탐색이 O(N)

```
1 → 5 → 23 → 41 → 60 → 87 → 99
```
87을 찾으려면 처음부터 한 칸씩 걸어야 한다.

## 해법: 위에 급행 층을 만든다

```
Level 2:  1 ─────────────────→ 60 ─────────→ 99      (초급행: 듬성듬성)
Level 1:  1 ────→ 23 ────────→ 60 ──→ 87 ──→ 99      (급행)
Level 0:  1 → 5 → 23 → 41 → 60 → 87 → 99             (완행: 전부 있음)
```

**87 탐색 과정:** 맨 위층에서 출발 → 1에서 60으로 점프(87보다 작으니 OK) → 60에서 99는 지나치니까 한 층 내려감 → 60에서 87로 점프 → 도착. 큰 걸음으로 건너뛰다가, 지나칠 것 같으면 아래층으로 내려간다.

## 성능

각 노드를 몇 층까지 올릴지는 동전 던지기(확률 1/2)로 정한다. 평균 층수가 log N이 되어 **탐색/삽입/삭제 모두 O(log N)** — 균형 이진 트리(레드블랙 트리)와 같은 성능.

## Redis가 트리 대신 skip list를 쓴 이유

1. **구현이 단순** — 균형 트리는 회전 연산이 복잡하다.
2. **범위 조회가 자연스러움** — `ZRANGE`(범위 조회)는 맨 아래층 연결 리스트를 그냥 따라가면 된다.

(Redis 개발자 antirez가 실제로 밝힌 이유)
